# Game AI Insight Hub 设计规格

## 1. 项目目标

构建一个可部署到 GitHub Pages 的高保真单页 Demo，用于产品经理线下面试。产品面向游戏公司内部员工，将外部 AI 新闻、模型更新、开源项目、论文与行业案例转化为可操作的游戏研发情报。

首屏必须清楚传达：这不是普通新闻日报，而是连接“AI 动态、岗位影响、游戏研发场景、落地判断与内部知识沉淀”的工作台。

## 2. 技术架构

- Vite、React、TypeScript。
- 原生 CSS，全局设计令牌统一管理颜色、间距、圆角和阴影。
- 所有数据来自 `src/data/mockData.ts`，无后端与真实 API。
- 页面状态由 React `useState` 管理；收藏状态同步到 `localStorage`。
- 使用相对资源路径，确保构建产物可直接发布到 GitHub Pages。

## 3. 信息架构

应用包含固定顶部栏、左侧导航和主内容区域。左侧导航切换六个页面：

1. 今日 AI 简报：核心入口，包含摘要指标、筛选器和八条新闻卡片。
2. 岗位订阅：展示五类岗位的关注方向、推送频率、内容类型和示例推送。
3. AI 能力卡片库：展示六张可复用能力卡片。
4. 游戏研发应用场景：区分研发流程提效与游戏内能力嵌入。
5. 内容审核后台：审核列表与后台规则配置。
6. 数据反馈看板：内容质量、用户使用和业务价值指标。

顶部“生成今日简报”触发轻量 Toast；“进入能力卡片库”切换到能力卡片页面。

## 4. 视觉设计

视觉方向为“宣纸朱砂 × 现代研发工作台”：

- 背景使用暖宣纸色，侧栏使用墨黑色。
- 朱砂色用于主操作、选中状态、关键建议与高相关性信息。
- 旧金色用于少量分隔、编号和辅助强调。
- 标题、关键数字和栏目编号使用 `KaiTi, STKaiti, serif`；正文使用系统无衬线字体。
- 卡片保持清晰的中后台结构，以细描边、轻阴影和克制纹理营造材质感。
- 不使用具象祥云、龙纹或强装饰插画，避免削弱专业性。

桌面端采用固定侧栏与内容卡片流。小屏幕下侧栏转为横向导航，卡片和表格改为单列或可横向滚动。

## 5. 核心页面与组件

### 今日 AI 简报

- 顶部显示抓取量、入选量、平均相关性、转预研数等关键指标。
- 支持按岗位和内容标签筛选。
- 每条新闻展示标题、来源、时间、AI 摘要、游戏研发关系、岗位标签、内容标签、相关性评分、落地难度和推荐动作。
- 操作包括有用、收藏、不相关、转为预研；有用计数即时增加，收藏状态持久化。

### 岗位订阅

五个岗位使用独立卡片呈现关注方向、推荐频率、内容类型和示例推送。内容突出不同职能对同一 AI 动态的需求差异。

### AI 能力卡片库

六张能力卡片呈现能力说明、技术基础、应用场景、适用岗位、难度、风险、推荐动作和参考案例。强调“能力沉淀”而非新闻堆叠。

### 游戏研发应用场景

按“研发流程提效”和“游戏内能力嵌入”分组。每个场景展示说明、岗位、价值、风险和推荐优先级。

### 内容审核后台

审核列表支持将内容状态更新为已通过、需修改或不推送。后台配置区静态展示信息源、标签、推送规则、审核规则、敏感过滤和推送时间。

### 数据反馈看板

展示今日抓取、简报入选、平均相关性、有用反馈率、转预研和节省时间等总览数据，并使用进度条呈现三类指标。

## 6. 数据与状态

`src/types.ts` 定义新闻、岗位订阅、能力卡片、应用场景、审核内容和指标类型。`mockData.ts` 导出对应数据集合。

运行时状态包括：

- 当前页面。
- 岗位与标签筛选条件。
- 新闻收藏集合、有用计数、不相关和转预研状态。
- 审核列表状态。
- Toast 显示内容。

筛选条件使用“全部”作为默认值。若筛选无结果，页面显示明确空状态并提供清除筛选操作。

## 7. GitHub Pages

Vite `base` 配置为 `./`，使 `dist` 可在仓库子路径下工作。README 提供本地运行、生产构建、预览和 GitHub Pages 发布说明，并补充可选的 GitHub Actions 自动部署方式。

## 8. 验收标准

- 六个导航页面均可正常切换。
- 简报岗位与标签筛选有效。
- 收藏、有用、审核状态和 Toast 交互有效。
- 八个指定新闻主题、五类岗位、六张能力卡片及两类研发场景完整呈现。
- 桌面端首屏清晰表达产品差异化定位。
- 小屏幕下无不可访问内容。
- `npm run build` 成功，产物可由 GitHub Pages 静态托管。
